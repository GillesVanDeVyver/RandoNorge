Parking data

Fjellrute shows parking areas near the start of a planned route. That layer is derived from OpenStreetMap, which is licensed under the Open Database License (ODbL) 1.0. ODbL is a share-alike licence, and one of its terms is that the database behind a published work must itself be published. This page is that publication. The extract below is the same data the application queries — nothing withheld, nothing added.

  • parking-norway.geojson 39,676 parking areas in Norway · ~6 MB
  • LICENSE.txt ODbL 1.0 notice and attribution
  • README.md Provenance, filter rules, field definitions

What is in it

Every OpenStreetMap node and closed way in Norway tagged amenity=parking, as of the build date recorded in the README, excluding areas tagged access=private, access=no or access=permit, and excluding roadside parking (parking=lane, street_side, on_kerb, half_on_kerb, shoulder). Ways are reduced to the arithmetic centroid of their nodes. Multipolygon relations are not included.

The upstream extract held 47,422 amenity=parking features on 22 August 2026; 7,262 were dropped by the filters above and 484 were relations, leaving the 39,676 published here.

How to rebuild it yourself

You should not have to take our word for any of the above. The build script is in the repository and reads the public Geofabrik extract: 

pip install osmium
curl -O https://download.geofabrik.de/europe/norway-latest.osm.pbf
python scripts/parking/build_parking_extract.py norway-latest.osm.pbf \
    --publish-dir public/data/parking \
    --sql-out build/parking.sql

What you may do with it

Whatever ODbL allows, which is a great deal: copy it, distribute it, adapt it, and use it commercially. The conditions are that you credit OpenStreetMap and its contributors, and that if you distribute an adapted version of the database you do so under ODbL as well. The full text is linked above and governs; this paragraph is a summary and not a substitute for it.

Corrections

If a car park here is wrong, missing, or has changed its price, the place to fix it is OpenStreetMap itself, not us. An edit there reaches every application using the data, including this one, at the next monthly refresh. That is the better half of the bargain and the reason the layer moved to OSM in the first place.
